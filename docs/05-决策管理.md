# 05 · 决策管理（Decision Management）

## 一、核心理念：决策是一等公民

项目卡住往往不是沟通问题，是**决策问题**，而决策全埋在群聊和文档里。本模块把「决策」做成与任务、风险并列的一等公民对象——有结构、有生命周期、有自动化、有留痕。**这是市面上几乎没有、而我们最独特的能力。**

## 二、决策卡结构（必填项）

| 字段 | 规则 | 对应 |
|------|------|------|
| 决策标题 | 一句话，**决策导向**（「A vs B」而非纯问题） | 拆 |
| 背景与问题 | 事实层 | — |
| 选项 Options | **≥2**，每个含：描述、对进度/成本/范围/质量的量化影响、利弊、是否推荐 | 拆·推 |
| 决策人 Decider | **恰好一个**，禁止「团队讨论一下」 | 推 |
| 参与/知会人 | C（征询）/ I（知会） | 相关方 |
| 截止时间 Due | 硬截止，必填 | 追 |
| 影响等级 | 决定升级阈值与是否阻塞里程碑 | 控 |
| 关联对象 | 关联项目/里程碑/风险/任务（这决策卡住谁/什么） | 闭环 |

**创建护栏**：选项 < 2、无唯一决策人、无截止时间 → 系统拒绝创建。

## 三、生命周期状态机

```
草拟 → 待决策 → 已决 → 已执行 → 关闭
          ↓超时          ↑(转为变更/任务/风险)
        升级中 ──────────┘
任意状态 → 已撤销(作废)
```

**关键**：「已决」不是终点。决策必须被**执行**（生成变更/任务/风险）才能「关闭」——把决策和「追」的闭环焊在一起。
- 已决须记录：所选选项 + 决策人 + 时间 + 理由。
- 关闭前置：已生成至少一个落地动作并被确认。
- 已撤销须记原因；撤销后退出决策债与健康分计算，审计记录保留。

## 四、自动升级（把「推」自动化）

| 触发 | 系统动作 |
|------|---------|
| 到截止时间 50% | 提醒决策人 |
| 到截止时间 | 升级：通知决策人 + 其上级 + PMO，转「升级中」，开始计决策债 |
| 逾期 N 天 / 或阻塞里程碑在 Y 天内 | 强制升级到发起人/治理层 |
| 阻塞关键路径或里程碑的决策逾期 | **触发健康分一票否决 → 项目转红**；落地后自动重算 |

升级全自动，不靠 PM 催。

## 五、决策债（让不决策的成本可见）

- 决策债 = 逾期天数 × 影响等级权重，每日累加，落地即停息。
- 阻塞链可视化：A 决策卡 B 决策、B 卡任务。
- 决策债是健康分 S5 的主要输入；债值上升 → S5 下降。**不决策，分数就掉。**

## 六、留痕与防重开

- 决策为永久记录：谁提的、有哪些选项、谁拍板、何时、选了什么、**否决了什么及为什么**。
- **否决项留存**至关重要：防止同一问题被反复重新讨论（决策重开是巨大浪费）。
- 不可删除（可追加更正说明），满足审计与复盘。

## 七、联动（决策是枢纽）

| 决策类型 | 决策后自动产生 |
|---------|------------|
| 范围/进度/成本变更 | → 变更申请（走 CCB，重建基线）→ 控 |
| 质量风险接受 | → 风险登记（应对=接受）→ 控 |
| 资源/任务调整 | → 新任务或改派 → 追 |
| 里程碑 go/no-go | → 状态门流转 → 回 |

落地对象可从决策卡一键跳转；对象状态回流决策（如变更被驳回 → 决策回「待决策」）。

## 八、决策 RACI

| 角色 | 决策中 |
|------|------|
| 决策人 | A（唯一担责，拍板） |
| 提出人（常为 PM） | R（起草决策卡、推推进） |
| 参与人 | C（提供输入） |
| 知会人 | I（知晓结果） |

## 九、决策类型与默认 SLA

| 决策类型 | 默认决策人 | SLA |
|---------|----------|-----|
| 范围变更 | 发起人 | 2 工作日 |
| 进度/上线时间调整 | 发起人 | 1 工作日 |
| 资源增补 | 资源经理 | 2 工作日 |
| 质量风险接受 | 发起人 + PMO | 3 工作日 |
| 供应商/采购 | 采购负责人 | 3 工作日 |
| go/no-go 里程碑 | 治理委员会 | 5 工作日 |

## 十、与健康分的交汇

决策管理是健康分的关键输入（S5 + 阻塞性否决），健康分是决策升级的触发器（红 → 治理介入）。两者咬合：**决策落地 → 健康分回升 → 项目回正轨**，全程系统驱动。
