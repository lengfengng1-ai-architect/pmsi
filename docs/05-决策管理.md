# 05 · 决策管理（Decision Management）

## 一、核心理念：决策是一等公民

项目卡住往往不是沟通问题，是**决策问题**，而决策全埋在群聊和文档里。本模块把「决策」做成与任务、风险并列的一等公民对象——有结构、有生命周期、有自动化、有留痕。**这是市面上几乎没有、而我们最独特的能力。**

## 二、决策卡结构（必填项）

| 字段 | 规则 | 对应 |
|------|------|------|
| 决策标题 | 一句话，**决策导向**（「A vs B」而非纯问题） | 拆 |
| 背景与问题 | 事实层 | — |
| 选项 Options | **≥2 且结构化互斥**（AC-DM-01a），每个含：描述、对进度/成本/范围/质量量化影响、利弊、是否推荐 | 拆·推 |
| 决策人 Decider | **恰好一个**；影响达阈值时 ≠ 提出人（AC-DM-01b） | 推 |
| 参与/知会人 | C（征询）/ I（知会） | 相关方 |
| 截止时间 Due | 硬截止，≥now 且 ≤所阻塞里程碑（AC-DM-12b） | 追 |
| 影响等级 | 决定升级阈值与是否阻塞里程碑；**变更须证据化（AC-X02）** | 控 |
| 关联对象 | 关联项目/里程碑/风险/任务（阻塞关系可自动探测 AC-DM-12a） | 闭环 |

**创建护栏**：选项<2 或取向相同、无唯一决策人、无截止/截止不合理 → 拒绝创建。

## 三、生命周期状态机

```
草拟 → 待决策 → 已决 → 已执行 → 关闭
          ↓超时        ↑(派生变更/任务/风险)
        升级中 ────────┘
                       ↓落地被驳回/取消
              已执行 → 待决策(回退,重置计息)
              已执行 → 已撤销(结构化撤销)
草拟/待决策/已决/已执行 → 已撤销(作废)
```

**关键规则**：
- 「已决」须记录：所选选项 + 决策人 + 时间 + 理由。
- **关闭前置**：已生成至少一个落地动作（达已执行/已关闭、类型与选项一致、回链决策、与决策 N:1 绑定）并被独立确认（AC-DM-07a/b）。仅「已决」不可直接「关闭」。
- **回退弧（AC-DM-05a）**：落地动作被驳回/取消 → `已执行→待决策` 自动回流，重置决策债计息时钟并标"回退"——**消除"已执行"死锁**。
- 已撤销须记结构化原因；「已实际执行」非合法撤销理由；撤销后退出决策债与健康分计算，审计记录保留。

> 状态机完整图见 [docs/07 图4](07-产品架构图.md)；任务/风险/变更/复盘状态机见 docs/07 同章。

## 四、自动升级（把「推」自动化）

| 触发 | 系统动作 |
|------|---------|
| 到截止时间 50% | 提醒决策人 |
| 到截止时间 | 升级：通知决策人 + 其上级 + PMO，转「升级中」，开始计决策债 |
| 逾期 **N=3** 天 / 或阻塞里程碑在 **Y=5** 天内 | 强制升级到发起人/治理层 |
| 阻塞关键路径或里程碑的决策逾期 | **触发健康分一票否决 → 项目转红**（AC-DM-12）；落地后自动重算 |

**升级可靠性（AC-DM-13a）**：升级目标须可解析；解析失败默认升级 PMO/发起人；逾期/过半后改 due date 受限且审计，**逾期状态粘滞——改期不重置计息时钟**。
**升级中硬超时（AC-DM-13b）**：升级中设硬超时 **T2=5 工作日**，T2 后自动上抛组合层并允许治理代决（CCB/治理委员会代决关闭或改派）；决策人=发起人/PMO（顶层）时升级路径强制跳 CCB，避免"自升级到自己"空转。

升级全自动，不靠 PM 催。

## 五、决策债（让不决策的成本可见）

- 决策债 = 逾期天数 × 影响等级权重（**默认权重 高=3/中=2/低=1，PMO 可配**；影响等级须证据化 AC-X02），每日累加，落地即停息。
- **跨项目决策**：指定一个"主项目"承担 S5 计分，其他关联项目显示"受影响"不重复扣分（AC-DM-26）。
- 阻塞链可视化：A 决策卡 B 决策、B 卡任务。
- 决策债是健康分 S5 的主要输入；债值上升 → S5 下降。**不决策，分数就掉。**

## 六、留痕与防重开

- 决策为永久记录：谁提的、有哪些选项、谁拍板、何时、选了什么、**否决了什么及为什么**。
- **否决项留存**至关重要：防止同一问题被反复重新讨论（决策重开是巨大浪费）。
- 不可删除（可追加更正说明）。新建同类决策提示历史（AC-DM-18，P1）；新决策与近 N 天已撤销决策做相似度匹配，超阈值须 PMO 解锁（防撤销+克隆刷时钟）。

## 七、联动（决策是枢纽）

| 决策类型 | 决策后自动产生 |
|---------|------------|
| 范围/进度/成本变更 | → 变更申请（走 CCB，重建基线）→ 控 |
| 质量风险应对（**规避/转移/减轻/接受**四策略，见 AC-RISK-02） | → 风险登记 → 控 |
| 资源/任务调整 | → 新任务或改派 → 追 |
| 里程碑 go/no-go | → 状态门流转 → 回 |

落地对象可从决策卡一键跳转；对象状态回流决策（如变更被驳回 → 决策经 `已执行→待决策` 回退）。

## 八、决策 RACI

| 角色 | 决策中 |
|------|------|
| 决策人 | A（唯一担责，拍板） |
| 提出人（常为 PM） | R（起草决策卡、推推进） |
| 参与人 | C（提供输入） |
| 知会人 | I（知晓结果） |

> RACI 权威定义见 [docs/11 §六](11-权责与访问范围设计.md)。

## 九、决策类型与默认 SLA

| 决策类型 | 默认决策人 | SLA |
|---------|----------|-----|
| 范围变更 | 发起人 | 2 工作日 |
| 进度/上线时间调整 | 发起人 | 1 工作日 |
| 资源增补 | 资源经理 | 2 工作日 |
| 质量风险接受 | 发起人 + PMO | 3 工作日 |
| 供应商/采购 | 采购负责人 | 3 工作日 |
| go/no-go 里程碑 | 治理委员会 | 5 工作日 |

> 「治理委员会 = CCB（或其授权上级）」，全文统一术语（见 docs/10 术语表）。

## 十、与健康分的交汇

决策管理是健康分的关键输入（S5 + 阻塞性否决），健康分是决策升级的触发器（红 → 治理介入）。两者咬合：**决策落地 → 健康分回升 → 项目回正轨**，全程系统驱动。
