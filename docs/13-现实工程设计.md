# 13 · 现实工程设计（审查补丁）

> 本文件回应设计审查（docs/12）的 C8（集成/迁移/通知三大缺口）与 H12（合规/移动/采纳/多租户/搜索/报表/商业模式/国际化/AI）。前三节给出可落地子设计，其余给出关键决策与范围。仍属业务/产品层面，不含技术实现细节。

---

## 一、集成设计（C8）

设计反复承诺"集成而非自建" IM/文档/代码/财务——本节把这个承诺落实。

### 1.1 集成方向与粒度
| 方向 | 含义 | 默认 |
|------|------|------|
| 推（系统→外部） | 决策升级/状态变更推到 IM/邮件 | 默认开 |
| 拉（外部→系统） | IM/邮件回执、代码 commit、财务凭证拉回 | 按对象 |
| 双向同步 | 决策卡 ↔ IM 卡片、任务 ↔ 文档 | 关键对象 |

**同步粒度**：项目 / 任务 / 决策 / 交付物 / 工时。粒度越细冲突越多，默认按"对象级"同步， Conflict 策略 = 系统为准 + 留痕外部修改建议。

### 1.2 集成对象分类（MVP 不必全做，先分类）
| 类别 | 代表 | MVP |
|------|------|:---:|
| 即时通讯 | 钉钉/企微/飞书/Slack/Teams | P1（决策卡↔IM 双向优先） |
| 文档 | Confluence/Notion/飞书文档 | P2 |
| 代码 | GitLab/GitHub/Gitee | P2 |
| 财务 | SAP/Oracle/金蝶/用友 | P2（只拉凭证，不写总账） |
| 身份 | SSO(SAML/OIDC)、SCIM 用户生命周期 | P1 |

### 1.3 决策卡 ↔ IM 双向闭环（护城河依赖）
"决策禁止在聊天里发生"要求：IM 里发起的讨论可**一键转决策卡**（带上下文回流）；决策卡审批可**在 IM 卡片内直接拍板**，结果回流系统并留痕。这是决策管理能否落地的关键体验。

### 1.4 开放能力
- Webhook / 事件订阅（对象级权限）
- 开放 API（CRUD + 状态机迁移），权限遵循 docs/11
- 集成失败：重试 + 幂等键 + 对账任务 + 降级（IM 不通则站内+邮件）

## 二、数据迁移与冷启动（C8）

### 2.1 导入映射
| 来源 | 关键映射 |
|------|---------|
| Jira | Issue→任务、Sprint→里程碑/迭代、优先级、自定义字段→交付物/验收 |
| MS Project | 任务/依赖/基线/资源→工时、甘特→进度 |
| 飞书项目/Asana/Trello | 任务/看板/成员 |
| Excel | 自由映射向导（列映射+校验） |
| 禅道/Redmine | Bug→风险/问题、任务、项目 |

处理：字段冲突人工裁决、ID 映射表保留、增量同步（迁移后双跑期）。

### 2.2 冷启动与经验库种子
- **历史项目导入做经验库 bootstrap**：导入的历史项目自动提取"复盘资产"种子，避免经验库空转。
- 模板库初始化：随产品交付行业模板（研发/工程/实施），PMO 可改。
- 新组织 onboarding：提供示范项目（含已填好的决策/风险/任务），让用户"看到一个跑通的项目"而非空白。

> 不做迁移的后果：新系统空白启动 → 健康分因缺数据强制"灰"（AC-HS-04a）→ 价值证不出 → 死循环。迁移是破局点。

## 三、通知与提醒策略（C8）

强制规则 + 无防骚扰 = 第一周被拉黑。本节是自动化引擎的直接依赖。

### 3.1 渠道与降级
站内 → IM → 邮件 → 移动推送；按优先级与用户偏好选渠道，降级链自动衔接。

### 3.2 防骚扰
- **聚合 + 摘要**：同一对象/同一人的多条事件合并为摘要（如"你有 3 个决策逾期"）。
- **频次封顶**：每人每日 N 条上限（可配），超限转"每日摘要"。
- **免打扰窗口**：跨时区、节假日延后（依赖工作日历，见 §8）。
- **优先级分级**：否决触发/阻塞里程碑 = 高（即时）；一般逾期 = 中（摘要）；知会 = 低（汇总）。

### 3.3 订阅偏好与通知中心
- 用户可订阅"哪些事件、哪个渠道"。
- **通知中心作为一等对象**（与决策/任务并列）：汇总、标记已读、过滤、归档。
- **双向通知**：从通知直接执行动作（拍板、确认闭环、审批），不必进系统逐层点。

## 四、合规 / 审计 / 隐私（H12）

| 项 | 要求 |
|----|------|
| 审计日志 | 范围=所有权限敏感动作；append-only/WORM 防篡改；可查询；保留期按合规（默认 ≥3 年） |
| 等保 | 私有部署目标等保 2.0 三级（企采常见门槛）；SaaS 视客户 |
| 主体权利（GDPR/个保法） | 访问/更正/删除/可携带；**决策永久记录 vs 删除权冲突** → 被决策人撤回同意时"脱敏+保留审计骨架"而非物理删 |
| 留存期 | 健康分历史、决策记录、归档项目按策略保留；超期自动归档/脱敏 |
| 加密 | 传输 TLS；静态加密；敏感财务字段字段级加密 |
| 备份/灾备 | RPO/RTO 目标定义；定期恢复演练 |

## 五、移动端 / 离线（H12）

- **形态**：MVP 优先 PWA/小程序（决策拍板、任务确认、审批的关键路径）；原生 App 视预算。
- **关键路径移动化**：决策人/发起人主要是高管 → 必须能在手机拍板，否则决策 SLA 崩。
- **离线**：出差/会议/弱网下查看 + 操作（决策/确认），上线后冲突合并（乐观锁）。
- **推送**：APNs/FCM/厂商通道（华为/小米等）。

---

## 六、Onboarding 与渐进式强制（H12）

系统核心是"逼"——对习惯微信群+Excel 的团队是冲击式上线。

- **渐进式强制**：先提醒后阻止、先试点后全员；PMO 可调"严格度"（宽松/标准/严格）。
- **示范项目 + 空状态引导**：每个角色（PM/团队/决策人/发起人）首次引导。
- **Champion / 内部教练**：试点项目配教练。
- **采纳指标**（纳入北极星）：活跃度、完成率、**绕过率、撤销率、敷衍率**（自审/空交付物/废话资产占比）。

---

## 七、Program 层与多租户（H12）

- **Program（项目集）层**：补进三层架构 → **Portfolio / Program / Project / Delivery**。Program 管相关项目协同、共享里程碑、跨项目依赖、项目集健康分。
- **多租户（如做 SaaS）**：数据隔离、跨租户禁穿、租户内多组织；子公司/事业部/业务线层级；跨组织用户身份映射。
- **形态决策**（需拍板）：开源 / SaaS / 私有部署？——反过来约束技术架构与合规门槛。

---

## 八、国际化 / 时区 / 工作日历（H12）

- **工作日历对象**：组织/项目/个人日历（节假日、调休）——**SLA 依赖它**（决策 SLA、升级阈值按工作日算）。
- **时区**：项目时区 vs 用户时区 vs UTC 存储统一。
- **多语言**：至少 zh-CN/en，i18n 框架；日期/数字/货币格式；周起始日、财政年度。
- **币种**：成本币种与汇率（多币种项目）。

---

## 九、搜索 / 筛选 / 批量（H12）

- 全局搜索（决策/任务/交付物/风险）；列表筛选（PM/决策人/健康灯/逾期/项目）；排序（优先级/紧急度/债值/影响）；批量操作（改派/关闭/状态/归档/导出）；分页与大数据量性能下限。

---

## 十、报表 / 导出（H12）

- **MVP 至少**：基于健康分下钻自动生成周报/状态报告（否则 PM 回 Excel 维护双轨）。
- 导出：PDF/Word/Excel/CSV/飞书文档/Confluence；定时订阅 + 邮件分发；按角色报表形态；图表（燃尽/燃起/累积流/EVM 曲线/决策债趋势）。

---

## 十一、商业模式 / GTM（H12，需拍板）

- 形态：开源（引流）/ SaaS（中小）/ 私有部署（金融政企）。
- 定价：按用户 / 项目 / 功能层级 / 部署形态。
- 目标客户：行业、规模、PMO 成熟度；GTM 顺序（先 PMO 成熟的金融/政企，还是中小研发？）。
- 竞品反制：Jira/飞书项目/Asana 若抄"决策卡"怎么应对 → 押在**反 gaming + 经验库 + 健康分双轨**这些难抄的组合上。
- 指标：续费/留存/NRR。

---

## 十二、AI 副驾可行性（H12）

AI 副驾是四大护城河之一，须论证而非空许：

- **数据准备**：历史项目语料、RAG/向量库、上下文边界。
- **模型策略**：调用 API / 自建 / 混合；成本控制。
- **人在回路**：AI 建议 + 人确认 + 留痕；**AI 起草的 WBS/决策选项/风险，R 仍归人**。
- **幻觉防护**：决策选项/风险/影响估算须过校验闸；**不污染 AC-X02 的"真实可追踪"根基**。
- **隐私**：AI 不看敏感预算/薪酬（字段级过滤后再送模型）。
- **指标**：建议采纳率、修正率、误报率。

## 小结

本文件把 docs/12 审查的"现实工程盲区"从"完全没设计"推进到"有范围、有关键决策、有 MVP 取舍"。其中 **集成（决策卡↔IM）、数据迁移（破冷启动死循环）、通知防骚扰** 三项是 MVP/P1 的直接依赖，应优先细化；**商业模式/形态决策** 需产品/商业侧拍板，它会反向约束多租户、合规、技术架构。
