## 图 1 · 总体产品架构（三层 + 横切）

价值链自上而下：用户驱动 → 组合层 → 项目层 → 执行层。横切能力贯穿三层。

```mermaid
flowchart TB
    subgraph ACT["用户角色 & 外部集成"]
        U1["高管 / 发起人"]
        U2["PMO"]
        U3["项目经理 PM"]
        U4["团队成员"]
        U5["系统管理员 Admin"]
        IM["即时通讯"]
        DOC["文档 / Wiki"]
        CODE["代码托管"]
        FIN["财务总账"]
    end

    subgraph L1["组合层 Portfolio — 管项目该不该立项"]
        A1["组合与立项"]
        A2["战略评分"]
        A3["容量规划"]
        A4["stage-gate 治理"]
    end

    subgraph L2["项目层 Project — 管项目怎么做对（五字）"]
        B1["拆 · WBS与责任分解"]
        B2["控 · 基线/变更/风险/EVM"]
        B3["推 · 决策管理"]
        B4["追 · 任务闭环执行"]
        B5["回 · 复盘与经验库"]
    end

    subgraph L3["执行层 Delivery — 管活儿怎么做完"]
        C1["任务 / 看板 / 甘特"]
        C2["工时"]
        C3["交付物"]
    end

    subgraph CC["横切能力（贯穿三层）"]
        H1["项目健康分"]
        H2["自动化引擎"]
        H3["AI 副驾"]
        H4["经验库 / 组织过程资产"]
        H5["权限 / RACI"]
    end

    U1 --> L1
    U2 --> L1
    U3 --> L2
    U4 --> L3
    L1 --> L2 --> L3
    CC -. 支撑 .-> L1
    CC -. 支撑 .-> L2
    CC -. 支撑 .-> L3
    ACT <--> CC
```

**读图要点**
- **集成而非自建**：IM/文档/代码/财务只接入、不自造。
- **横切层**：健康分、自动化引擎、AI 副驾、经验库、权限——三层都用，放侧面贯穿。
- 角色全集（含 Admin、发起人、决策人、CCB、相关方）见 [docs/11](11-权责与访问范围设计.md)；图1 只列主操作角色。

## 图 4 · 决策生命周期状态机（含回退弧）

```mermaid
stateDiagram-v2
    [*] --> 草拟
    草拟 --> 待决策: 提交（≥2选项+决策人+截止）
    待决策 --> 升级中: 到期未决·自动升级
    待决策 --> 已决: 决策人拍板
    升级中 --> 已决: 决策人/治理代决
    已决 --> 已执行: 生成落地动作
    已执行 --> 关闭: 动作确认闭环
    已执行 --> 待决策: 落地被驳回/取消(回退)
    草拟 --> 已撤销
    待决策 --> 已撤销
    已决 --> 已撤销
    已执行 --> 已撤销: 结构化撤销
    关闭 --> [*]
    已撤销 --> [*]
```

**读图**：`已执行→待决策` 回退弧消除"落地失败死锁"；升级中有硬超时 T2 可由治理代决。

## 图 5 · 任务状态机

```mermaid
stateDiagram-v2
    [*] --> 未开始
    未开始 --> 进行中: 领取/分派
    进行中 --> 已提交: 上传交付物
    已提交 --> 已关闭: 确认人确认闭环(非自审)
    已提交 --> 进行中: 确认人打回(验收不通过)
    进行中 --> 已撤销
    未开始 --> 已撤销
    已关闭 --> [*]
    已撤销 --> [*]
```

**读图**：`已提交`即"完成但未闭环"态——必须有交付物 + 独立确认才到 `已关闭`。

## 图 6 · 风险状态机

```mermaid
stateDiagram-v2
    [*] --> 已识别
    已识别 --> 已分析: 评估等级+应对策略(规避/转移/减轻/接受)
    已分析 --> 应对中: 措施执行
    应对中 --> 已关闭: 高危须发起人/PMO确认
    已分析 --> 已发生: 风险实现
    应对中 --> 已发生: 风险实现
    已发生 --> [*]: 重分类为问题(保留记录,双计S4)
    已关闭 --> [*]
```

**读图**：高危风险关闭须独立确认（与任务/决策对称）；`已发生`转问题但原风险记录保留并继续计入 S4 直到问题闭环。

## 图 8 · 复盘状态机

```mermaid
stateDiagram-v2
    [*] --> 待复盘: 项目结项触发
    待复盘 --> 进行中: 结构化复盘(目标/范围/进度/成本/质量/满意度)
    进行中 --> 资产评审: 产出≥1结构化资产
    资产评审 --> 已入库: PMO抽审通过
    资产评审 --> 进行中: PMO打回(空话/不结构化)
    已入库 --> [*]
```

**读图**：复盘必须产出**结构化资产**且 PMO 抽审通过才能结项（AC-RET-02），堵"自由文本废话"漏洞。

## 图 9 · 项目健康分构成逻辑

```mermaid
flowchart TB
    subgraph INPUT["八维子分（各 0-100）"]
        S1["S1 进度 SPI"]
        S2["S2 成本 CPI\n+EAC/VAC/TCPI"]
        S3["S3 范围稳定"]
        S4["S4 风险健康"]
        S5["S5 决策健康"]
        S6["S6 质量健康"]
        S7["S7 闭环健康"]
        S8["S8 资源(8a)/相关方(8b)"]
    end

    INPUT -->|"加权 Σ 权重×子分"| COMP["合成分 0-100"]
    VETO["⚠️ 一票否决（按阶段启用）"]
    DATA["⚪ 有效维度<阈值 → 灰·评估中"]
    COMP --> THRESH{"阈值判定\n（取严）"}
    VETO -. 强制红 .-> THRESH
    DATA -. 不得绿 .-> THRESH
    THRESH -->|"≥80 且无否决 且维度足"| G["🟢 绿"]
    THRESH -->|"60-79 或子分<60"| Y["🟡 黄"]
    THRESH -->|"<60 或否决"| R["🔴 红"]
    COMP --> TREND["↗ / → / ↘ 趋势(≥3周期滑动)"]
    G --> ACTION["状态转换动作\n绿→黄:24h纠偏(可追踪)\n黄→红:48h恢复\n转好须迟滞≥2周期"]
    Y --> ACTION
    R --> ACTION
```

**读图**：双轨（合分管总体 / 否决管致命单点）取严；缺数据显"灰"不得绿；转好有迟滞防抖动。
