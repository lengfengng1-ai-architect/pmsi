# 18 · 安全合规

> 围绕"多租户 SaaS、强隔离、企业级合规（金融/政企路线）"。落地 docs/11 权限、docs/15 audit/evidence、docs/17 运维的安全侧。映射到关键 AC。

## 一、安全模型与信任边界

| 边界 | 信任 | 控制 |
|------|------|------|
| 边缘（Ingress/WAF） | 不可信流量 | TLS 终止、WAF、限流、Bot 防护 |
| 应用（FastAPI） | 已认证用户 | RBAC×范围、输入校验、守卫、审计 |
| 异步（Celery worker） | 内部 | 受限租户上下文、最小权限 DB 账号 |
| 数据（PG/对象存储） | 内部 | 加密、隔离、审计、备份 |
| 控制库 | 极敏感 | 跨租户身份/许可，最严访问控制 + 单独 DB 账号 |

## 二、认证与身份

- **会话**：JWT（短期 access + refresh），httpOnly+Secure+SameSite cookie；或纯 Bearer。
- **SSO**：OIDC（authlib）/ SAML 2.0；企业客户对接 IdP（Azure AD/钉钉/企微/Keycloak）。
- **SCIM 2.0**：用户生命周期自动同步（入职建账号+租户映射、离职停用→自动回收项目权限、归档项目转只读）。
- **MFA**：管理员/发起人/决策人等高权角色强制；敏感动作（go/no-go、基线变更）可要求 step-up。
- **会话治理**：登出吊销 refresh；异常并发登录告警。

## 三、授权（docs/11 的执行）

- **RBAC × 数据范围**：功能权限（岗位角色→action）+ 数据范围（项目成员/对象责任/组合/状态），全部在 `RequirePerm`+`ScopeFilter` 依赖强制（docs/16）。
- **对象级（ABAC）**：确认闭环须 `actor≠submitter`、决策须唯一决策人、高危风险关闭须发起人/PMO——服务层守卫。
- **Admin override 治理（AC-ADMIN-01）**：Admin 越权须双人确认或 24h PMO 复核；解除否决/跳 CCB 实时推 PMO；**系统禁止 Admin 承担业务 R/A**；override 全程审计。

## 四、多租户隔离

- **物理隔离**：一租户一库（docs/15），租户库无 `tenant_id`，库即租户；跨租户业务数据不可达。
- **引擎路由**：`tenant_id`→引擎，contextvars 注入会话；**严禁跨租户会话复用**（中间件强制每请求重置）。
- **控制库**：跨租户表（tenant/user/tenant_user）独立 DB 账号 + 行级管控；联邦查询仅限必要、白名单。
- **对象存储**：交付物/证据按租户前缀隔离 + 签名 URL 访问；跨租户路径校验。

## 五、数据保护 / 加密

| 层 | 方案 |
|----|------|
| 传输 | 全链 TLS（边缘终止后内网仍 mTLS 视合规）；HSTS preload |
| 静态 | PG 透明加密（TDE）/磁盘加密；对象存储服务端加密 |
| 字段级 | 敏感字段（成本、薪酬级工时）应用层字段级加密（KMS 信封加密），按角色脱敏返回（docs/11） |
| 密钥 | KMS 托管 + 轮换；信封加密（DEK/KEK）；密钥与数据分离；**永不出现在代码/日志** |
| 哈希 | 交付物/证据 `content_hash`（完整性、防空文件）；密码 argon2 |

## 六、审计与可追溯

- **业务审计** `audit_event`（租户库）：所有状态迁移/权限敏感动作，append-only（DB revoke UPDATE/DELETE + 触发器），同事务写入（docs/15/16）。
- **平台审计** `platform_audit`（控制库）：开租户、SSO 事件、Admin override、配置/密钥变更。
- **留存**：按合规默认 ≥3 年（金融等更长）；归档转 WORM（一次写多读）防篡改。
- **查询**：`GET /v1/admin/audit-events`（PMO/Admin），按实体/动作/人/时间检索；导出供审计。

## 七、合规

### 7.1 等保 2.0 三级路径（企采门槛）
覆盖物理/网络/主机/应用/数据/管理：网络隔离与入侵防护、主机加固与漏洞管理、应用 OWASP 防护与审计、数据加密与备份、管理制度与人员。私有部署可过三级测评；SaaS 按客户要求。

### 7.2 GDPR / 个人信息保护法
- **主体权利**：访问、更正、删除、可携带；导出接口。
- **删除权 vs 审计留存冲突**：用户注销/撤回同意时——**业务 PII 脱敏**（姓名/邮箱置占位），**审计骨架保留**（聚合状态迁移、决策记录脱敏但不可删，满足"决策永久记录"的治理需要）。
- **同意与目的**：明确数据用途；最小化采集。
- **数据留存与销毁**：按策略到期自动脱敏/归档/删除并记录。
- **跨境传输**：多区域部署按数据驻留要求（如 EU 数据不出区）；跨境需合法基础 + 告知。

## 八、应用安全（OWASP Top 10）

| 风险 | 对策 |
|----|------|
| 注入 | SQLAlchemy 参数化全文；无拼接 SQL；JSONB 用 ORM |
| 失效访问控制 | RBAC×范围 + ABAC 守卫（docs/11/16）；默认拒绝 |
| 加密失效 | 见 §五 |
| XSS | 前端默认转义；CSP nonce；禁 `dangerouslySetInnerHTML` 除非清洗 |
| CSRF | Cookie 认证用 SameSite + 双提交 token；Bearer 免 |
| SSRF | 集成/导入 URL 白名单 + 禁内网地址段 |
| 不安全反序列化 | 只用可信格式（Pydantic/JSON）；无 pickle |
| 已知漏洞组件 | uv.lock 锁定 + 漏洞扫描（见 §十） |
| 日志/监控不足 | 见 docs/17 可观测 + 审计 |
| 失效身份认证 | 见 §二 |

- **限流**：per-tenant + per-user + per-IP（Redis）；写操作更严。
- **输入校验**：Pydantic 全量校验；枚举/范围/长度；上传文件类型+大小+魔数校验。

## 九、API / 集成安全

- 集成用 OAuth2 受限 scope；webhook 出站签名（HMAC）+ 重试退避；入站 IP 白名单。
- 幂等键防重复（docs/16）；关键动作（审批/拍板）幂等。
- 决策卡↔IM 双向：IM 侧卡片动作验签、限时。

## 十、供应链与依赖

- `uv.lock` 锁全量；CI 跑漏洞扫描（pip-audit/`uv audit`）；镜像最小化 + 扫描（trivy）。
- 前端 SRI；第三方脚本最小化、审计。
- SBOM 产出随发布归档（合规审计）。

## 十一、密钥管理

- Secrets Manager / KMS；轮换策略；DB DSN/SSO secret/对象存储凭证/加密 KEK 全托管。
- 密钥泄露响应：轮换 + 审计追溯 + 受影响数据评估。

## 十二、安全开发与事件响应

- **开发期**：SAST（ruff/bandit/semgrep）+ 类型检查；密钥扫描（pre-commit/CI）；威胁建模（按信任边界）；依赖与镜像扫描。
- **发布前**：DAST + 渗透测试（年度/重大版本）。
- **事件响应**：检测（告警/审计异常）→ 遏制（隔离租户/吊销凭证）→ 根因 → 通知（按法规时限，如个保法 72h、GDPR 72h）→ 修复 + 复盘入库。
