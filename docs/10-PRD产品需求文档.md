## 1. 概述

### 1.1 背景
市面项目管理工具多停留在「任务跟踪 + 看板」，PMP 的高价值能力（范围分解、成本预算、风险与变更控制、相关方对齐、价值度量）普遍缺失或难用；决策埋在群聊里、复盘流于形式、项目健康靠感觉。

### 1.2 问题陈述
项目「做了不少、价值看不到」；范围蔓延无控制；风险事后救火；经验不沉淀；项目经理沦为「传声筒 + 催办员」。

### 1.3 产品定位
**让战略落地到交付、可度量、可复盘的项目经营系统**——把顶级 PM 的做事方式（拆、控、推、追、回）用 PMP 专业方法固化成不依赖个人能力的组织能力。

### 1.4 价值主张
- 给项目经理：从「天天催天天问」解放，专注判断与推动决策。
- 给管理层：一个数（健康分）说清项目行不行。
- 给组织：把一次项目的经验变成下一次项目的能力。

## 2. 目标用户与典型场景

| 角色 | 核心场景 |
|------|---------|
| 发起人/高管 | 看组合健康度、批章程与基线变更、go/no-go |
| PMO | 配模板/权重/SLA、组合治理、度量 |
| 项目经理 | 拆 WBS、控风险变更、推决策、追闭环、带复盘 |
| 团队成员 | 执行任务、报工时、上传交付物、确认闭环 |

**核心用户故事**：作为项目经理，我希望系统逼我「任务不带交付物就关不掉、决策超时就自动升级、风险无应对就报警」，这样我不用靠记忆和催办，项目自然有秩序。

## 3. 范围

### 3.1 MVP（P0）In Scope
立项/章程、WBS 与责任分解、任务与闭环执行、基线与变更控制(轻)、风险与问题、**决策管理+自动升级**、自动化(核心规则)、结构化复盘、健康分(轻)。

### 3.2 Out of Scope（MVP 不做）
组合层、EVM/CPI、决策债可视化、经验库跨项目复用、AI 副驾、相关方矩阵、自定义自动化、工时/资源、完整 CCB。（理由见 docs/08）

## 4. 功能需求详述

> 编号规则：`FR-<模块>-NN`。验收标准引用 docs/06 编号，**已整合 docs/09 反检验补丁**（标注 `[补]`）。优先级 P0(MVP)/P1/P2/P3。

### 4.1 立项与项目章程（P0）
**FR-PRJ-01** 创建项目并生成章程，含目标、范围摘要、发起人、项目经理、关键里程碑。
- **规则**：项目经理须被授权；立项即创建初步相关方清单。
- **AC**：章程字段完整方可提交；项目状态进入「规划中」。
- **优先级**：P0

### 4.2 WBS 与责任分解（P0）
**FR-WBS-01** 逐级分解工作分解结构到工作包。
- **规则**：任务创建强制带 **交付物 + 责任人 + 截止时间 + 验收标准**；缺一拒绝。「完成系统上线」类粗任务须展开为子环节方可「规划完成」。
- **AC**：无交付物的任务不可创建；RACI 每节点明确「执行/拍板/知会」。
- **优先级**：P0

### 4.3 任务与闭环执行（P0）
**FR-TASK-01** 任务执行与**闭环确认**。
- **规则**：区分「状态」与「闭环」——须**上传交付物 + 责任人确认关闭**才算闭环；「差不多了」不可标完成。任务关闭前过强制检查项（哪个版本/谁拍板/有无纪要/影响哪个节点）。
- **AC**：无交付物+确认的任务不可关闭；逾期/阻塞/无更新超 N 天自动推送。
- **优先级**：P0
- **[补] 反检验关联**：确认人须为责任人，禁自审（同 AC-DM-07b 思路）。

### 4.4 基线与变更控制·轻（P0）
**FR-BASE-01** 范围/进度基线锁定与变更申请。
- **规则**：基线一旦建立，触及范围/进度/成本须走变更申请（MVP 不走完整 CCB，记录影响+发起人确认）。
- **AC**：基线突破须有变更记录；非受控突破触发健康否决。
- **优先级**：P0（完整 CCB 见 P1 FR-CCB-01）

### 4.5 风险与问题（P0）
**FR-RISK-01** 风险登记与前置管控。
- **规则**：每条风险须有**应对措施 + 责任人 + 关闭时间**，否则状态永驻「未处理」并报警。客户「可能加需求」当场登记为变更候选项。
- **AC**：无应对的高危风险触发健康否决；CPI/SPI 阈值报警。
- **优先级**：P0

### 4.6 决策管理（P0 · 核心护城河）

**FR-DEC-01 决策卡创建**
- **规则**：必填 标题/背景/**≥2 选项**/唯一决策人/截止/影响等级/关联对象。
- **AC**：`AC-DM-01`；`AC-DM-02`；`AC-DM-03` 唯一决策人。
- **[补] AC-DM-01a** 选项结构化互斥（取向相同则拒）；**AC-DM-01b** 决策人≠提出人(达阈值)，截止 ≥now 且 ≤阻塞里程碑。
- **优先级**：P0

**FR-DEC-02 决策生命周期**
- **规则**：状态机 草拟→待决策→(超时→升级中)→已决→已执行→关闭 / 任意→已撤销。「已决」须记录所选+决策人+时间+理由；**关闭前置须有落地动作并被确认**。
- **AC**：`AC-DM-05/06/07/08`。
- **[补] AC-DM-07a** 落地动作须已执行/已关闭、类型一致、回链决策；**AC-DM-07b** 确认人须为责任人/决策人，禁自审；**AC-DM-07c** 撤销理由结构化，「已实际执行」非合法撤销，撤销率告警。
- **优先级**：P0

**FR-DEC-03 自动升级**
- **规则**：截止 50% 提醒；到期升级(决策人+上级+PMO)转「升级中」并计决策债；逾期 N 天/阻塞里程碑在 Y 天内强制升级发起人/治理。
- **AC**：`AC-DM-09/10/11/12/13`。
- **[补] AC-DM-12a** 阻塞关系声明或自动探测(任务"等待决策"即建链)；**AC-DM-12b** 决策截止 ≤ 所阻塞里程碑；**AC-DM-13a** 升级目标可解析、失败默认 PMO/发起人，逾期后改期受限且计息粘滞。
- **优先级**：P0

**FR-DEC-04 留痕与防重开**
- **AC**：`AC-DM-17/18/19`；永久记录含被否决项及理由，不可删。
- **优先级**：P0

**FR-DEC-05 联动**
- **规则**：按类型派生 范围/进度/成本变更→变更申请；质量风险接受→风险登记；资源/任务→任务；go/no-go→状态门。落地对象回链且状态回流。
- **AC**：`AC-DM-20/21/22`。
- **优先级**：P0

**FR-DEC-06 决策 RACI 与 SLA**
- **AC**：`AC-DM-23/24/25`；默认 SLA 见 docs/05 §九。
- **优先级**：P0

### 4.7 自动化·核心规则（P0）
**FR-AUTO-01** 硬编码核心规则：决策到期升级、任务逾期提醒、风险无应对报警、健康分阈值触发动作。
- **规则**：MVP 仅上述规则，**不做自定义引擎**（P1）。
- **AC**：`AC-DM-13` 升级全自动不依赖人工催办。
- **优先级**：P0

### 4.8 结构化复盘（P0）
**FR-RET-01** 收尾强制结构化复盘。
- **规则**：逐项过 目标达成/范围失控/进度偏差/成本/质量集中点/满意度；须**产出 ≥1 条可复用资产**（模板/清单/规则/预警项）方可结项。
- **AC**：空话复盘过不了关；资产入经验库。
- **优先级**：P0（跨项目复用见 P1 FR-KB-01）

### 4.9 健康分·轻（P0）
**FR-HEALTH-01** MVP 简易健康分。
- **规则**：4 信号（进度完成度/SPI 近似、逾期任务、阻塞逾期决策、高危未关风险）+ 关键否决（关键路径滑移、基线非受控突破）→ 粗粒度红黄绿；标注「数据不全」。
- **[补] AC-HS-04a** 有效维度 < 阈值显示「灰·评估中」，不得绿；**AC-HS-06a** 恢复方案须为可追踪行动项(非文本)，未进行中否决不解除；**AC-HS-06b** 否决按阶段标注启用，缺数据显示「未启用」，禁静默放行绿。
- **优先级**：P0（完整 8 维见 P1）

## 5. 业务规则总览（固化清单）

| 规则 | 出处 |
|------|------|
| 任务须带交付物/责任人/截止/验收方可创建 | 拆 |
| 风险须有应对/责任人/关闭时间，否则报警 | 控 |
| 决策须 ≥2 互斥选项 + 唯一决策人 + 合理截止 | 推 |
| 决策超时自动升级，不依赖人工 | 推 |
| 任务闭环须交付物 + 独立确认 | 追 |
| 复盘须产出 ≥1 可复用资产方可结项 | 回 |
| 凡提交/确认/解除类动作须产出可追踪对象，禁纯文本（**AC-X01**） | 横切 |
| 状态变更全程留痕，不可删（可追加更正） | 治理 |

## 6. 非功能需求（业务级，不含技术实现）

| 类别 | 要求 |
|------|------|
| **治理** | PMO 可配置权重/阈值/SLA；权重变更仅对未来生效，历史锁定 |
| **数据完整性** | 所有关键状态变更留痕、可回溯任意时刻快照；记录不可物理删除 |
| **权限** | 基于角色与 RACI；决策人/确认人唯一可执行性校验 |
| **合规/隐私** | 不存敏感财务全账（靠集成外部财务）；外部数据最小化接入 |
| **自动化可靠性** | 关键动作（升级/否决/提醒）系统自动执行，降人工依赖 |
| **可裁剪** | 支持预测/适应/混合模式，按项目类型开关流程 |

## 7. 成功指标与北极星

### 7.1 MVP 北极星（4 条全中即成功）
1. 无交付物的任务关不掉；
2. 超 SLA 的决策系统必升级；
3. 无应对的高危风险必报警；
4. 收尾产出可复用经验。

### 7.2 量化指标（产品级）
- 范围非受控变更率 ↓
- 决策平均关闭时长 ↓、决策债总值 ↓
- 复盘资产被后续项目复用率 ↑
- 健康分对项目最终成败的预测准确度 ↑
- 项目经理人均管理项目数 ↑（效率）

## 8. 依赖与假设

| 类型 | 内容 |
|------|------|
| 假设 | 组织结构（汇报关系）数据可用，否则决策升级无目标（见 AC-DM-13a 兜底） |

| 外部依赖 | 即时通讯/文档/代码/财务靠**集成**，不自建 |
| 假设 | 管理层授权系统「强制动作」（决策卡/闭环/复盘），否则规则被绕过 |

## 9. 风险与对策
见 docs/08 §七。核心：MVP 偏重→死守脊柱四件套；自动化拖慢→只硬编码两条规则；决策阻力大→从高影响低频决策切入。
